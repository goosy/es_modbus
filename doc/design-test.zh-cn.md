# 设计：测试套件

> 本文是 [design-test.md](design-test.md) 的中文译本。

本库**如何**测试：什么在哪里测、套件如何运行，以及所需的环境。这是从 [design.zh-cn.md](./design.zh-cn.md)
拆出的一个主题。

## 原则

- 通过公共 API 进行的测试（单个类对接伪对端、两个类端到端互测、构建产物）检查 `spec-*` 系列规定的
  行为，而不是以当前代码为准。`src/util.js` 中各函数的测试检查 `design.zh-cn.md` 描述的机制。
- 由 `src/util.js` 中纯函数实现的规则，在那里逐条测试。类的测试只检查类确实应用了它：通过类测一两个
  用例，不再把整张表重测一遍。
- 代码尚未满足规格之处，测试仍然陈述规格要求的行为，并标记为 `{ todo }`，这样套件能显示缺少什么，
  而不会失败；修复后移除该标记。
- 不需要额外的测试依赖：套件使用 Node.js 内置的运行器（`node:test`、`node:assert/strict`）。
  类型检查使用类型声明本来就需要的 `typescript`。
- 除构建产物测试外，测试直接从 `src/` 导入，因此源码测试无需构建。

## 分层

`test/util.test.js` 覆盖 `src/util.js`；`test/client.test.js` 和 `test/server.test.js` 分别单独
覆盖一个类；`test/tcp.test.js` 和 `test/serial.test.js` 分别通过回环 TCP 和一对串口对两个类做端到端测试；
`test/serial-bridge.test.js` 在两个伪串口之间的模拟串行线路上检查串口路径的时序（按波特率逐字节到达、
超过线路静默时间的停顿、迟到的应答、设备掉线）；`test/udp.test.js` 覆盖 UDP 家族，既让每个类
单独面对一个原始 UDP 对端，也通过回环 UDP 对两个类做端到端测试；`test/bundle.test.js` 覆盖构建产物 `dist/modbus.js`
及 `native/` 和 `dist/modbus.d.ts`；`test/types.ts` 从不运行，只由 `tsc -p test` 对照发布的类型声明做
类型检查，通过 `exports` 以 `es-modbus` 导入：它像 README 那样调用 API，并用 `@ts-expect-error`
标出声明必须拒绝的误用（没有传输方式、两个传输方式、不适用的选项）。夹具（包括模拟串行线路 `create_serial_bridge`）都位于 `test/helpers.js`；其中的 `parse_link()`
为串口测试和串口测试启动脚本解析 `MODBUS_SERIAL_PORTS`。串口测试的辅助代码不另设测试：取值不合法时，
串口测试运行失败并注明原因。

## 命令

| 命令                 | 作用                                                                  |
| -------------------- | --------------------------------------------------------------------- |
| `pnpm test`          | 先运行 `pnpm build` 和 `tsc -p test`，再用 `node --test` 运行所有 `test/**/*.test.js`。 |
| `pnpm test:coverage` | 同上，并输出仅限 `src/**` 的内置覆盖率报告。                          |

也可以直接运行 `node --test`；此时若 `dist/modbus.js` 不存在，或比 `src/` 中任一文件旧，构建产物测试
会被跳过。

## 伪对端与隔离

- 服务端在 `127.0.0.1` 上以端口 `0` 监听，因此每个测试都会得到一个空闲的临时端口，各测试文件可以
  并行运行。公开选项不接受端口 `0`，因此测试服务端先用固定目标构造，再把它的 `port` 属性设为 `0`
  （`test/helpers.js` 中的 `ephemeral_server` 和 `start_udp_server`）。
- UDP 测试使用 `127.0.0.1` 上的原始 `node:dgram` 套接字充当伪设备或客户端（`start_fake_udp_device`、
  `raw_udp_socket`），从而可以让应答来自另一个端口、拆到几个数据报里，或迟到。被占用的本地端口
  通过把一个原始套接字绑定到该端口来制造。
- 客户端测试使用一个原始的 `node:net` 服务端充当伪从站，从而可以检查线路上的确切字节，并构造格式
  错误或乱序的应答。
- 服务端测试在不需要网络时通过伪套接字或伪串口把帧送入 `on_data`；在真实传输有意义时使用原始的
  `node:net` 套接字。
- 串口生命周期测试把 `src/serial.js` 的串口工厂替换为创建伪串口的工厂（`set_serial_port_factory`，
  不属于公共 API），因此不需要串口硬件，也不需要原生绑定。

## 串口测试

串口测试在一条链路上运行，链路的两端由环境变量 `MODBUS_SERIAL_PORTS` 设置。
串口测试默认关闭，因为一台机器不一定有串口，无论虚拟的还是物理的：未设置该变量时，串口测试组被跳过。

该变量有三种形式。第一端总是串口设备路径；第二端全是数字时是本机 UDP 端口，否则是串口设备路径。
通常由启动脚本 `pnpm test:serial` 设置它（见下文“串口测试启动脚本”）；也可以手动设置，例如用
`node --test --experimental-test-coverage` 运行串口测试时。

| 形式                           | 链路                                                                                |
| ------------------------------ | ----------------------------------------------------------------------------------- |
| `COM11,COM12`                  | 两个像零调制解调器线缆那样相连的串口：一对 com0com 端口，或两个接在一起的物理串口。 |
| `COM3,502`                     | 一个串口接到一台串口转 UDP 的透传设备，透传设备把串口数据发往测试机的 UDP 端口 502。 |
| `COM3,502,192.168.1.10:4001`   | 同上，并指明透传设备：数据报发往该地址和端口，只接受来自该地址的数据报。            |

- **只用透传设备。** 透传设备必须原样转发字节。不支持 Modbus RTU 转 TCP/UDP 网关：它会改写帧，测试就
  看不到线路上的字节。测试在 UDP 端使用 RTU-over-UDP。透传设备怎样把串口字节打包成数据报没有要求：
  RTU-over-UDP 把同一对端的数据报当作一条字节流来定界（见 `spec-protocol.md` 的“Datagrams”）。
- **透传设备的设置。** 透传设备要设成把串口数据发往测试机的本机 UDP 端口，串口一侧按下文的串口参数
  设置。测试在本机所有 IPv4 地址上绑定该端口；各测试组依次绑定并释放它。UDP 没有连接，所以测试组从不等待透传设备。
- **学到的远端。** 不给远端时由预检学到：把探测帧从串口带到本机端口的数据报的发送方（地址和端口）。
  此后这次运行只向该地址和端口发送，也只接受来自该地址和端口的数据报。透传设备只在串口一侧收到字节
  时才发送，所以局域网上其他向同一端口发数据的透传设备，在其串口空闲时不会造成干扰：只有接在被测串口
  上的那台会把探测帧发出来（见到过：两台透传设备都发往 `:502`，被测串口接哪一台都能通过）。探测期间
  若有其他透传设备的数据报到达，收到的字节就不是探测帧，预检失败；它不会被悄悄当成远端。
- **给定的远端。** 远端 `<address>:<port>` 是一个 IPv4 地址（不接受主机名）和透传设备接收数据的端口。
  两种情况需要它：运行期间另有透传设备向同一端口发数据，例如它的串口接在一条正在通信的总线上，或者它
  会发心跳包、注册包；或者透传设备发送数据的源端口不是它接收数据的端口，学到的端口发不到它。给定远端
  后，数据报发往该地址和端口，来自该地址的数据报不论源端口都接受（在 `Modbus_Client` 上即
  `any_source_port`）。
- **应答等待时间。** 原始对端对应该到来的字节（应答、请求、探测帧）最多等 1 s，与这些测试组中客户端的
  `timeout` 相同。透传设备可能把串口字节攒上几百毫秒才作为数据报发出（见到过：一个来回约 400 ms）。
  字节提前到达就结束等待，所以快的链路不会多花时间。
- **串口参数。** 测试组以 9600 波特、8 数据位、无校验、1 停止位（9600 8N1）运行，这是 Modbus 常用的
  默认值。透传设备的串口一侧也须设成相同参数。
- **波特率扫描。** 两个串口时，先做一轮扫描：在 1200、2400、4800、9600、19200、38400、57600 和
  115200 波特（8N1）下，各由对端发一个请求并检查应答。某个波特率失败不算错误，因为端口不一定支持
  所有波特率。扫描完成时列出所有成功的波特率，至少一个波特率成功算扫描通过；一个都不成功时扫描失败，
  其余串口测试组不再运行。有 UDP 端时不做扫描，因为透传设备的波特率是固定的。
- **双串口时测试组的波特率。** 9600 是工业默认波特率，只要成功列表中有 9600，其余串口测试组就用它；
  只有成功列表中没有 9600 时，才用列表中的第一个波特率。
- **角色。** 两个串口时，服务端一侧打开第一个端口，对端（原始串口或 `Modbus_Client`）打开第二个。
  有 UDP 端时，被测的库在两种角色下都位于串口一侧，UDP 端是它的对端：原始套接字、RTU-over-UDP 的
  `Modbus_Client`（用 `local` 绑定本机端口）或 RTU-over-UDP 的 `Modbus_Server`。因此两个类的端到端
  测试组运行两遍，串口一侧各用一个类。RTU-over-UDP 服务端把应答发回请求的来源地址和端口，所以当
  透传设备发送数据的端口不同于给定远端的端口时，服务端位于 UDP 端的那一遍被跳过。
- **设置即必需。** 串口测试组运行前会做一次预检：打开每一端。有 UDP 端时，还让一个探测帧（一个没有
  设备应答的读请求）沿两个方向各穿过透传设备一次，并要求在应答等待时间内收到相同的字节：先从串口到本机 UDP
  端口，这同时给出学到的远端和透传设备发送数据的端口；再从 UDP 端到串口。设置了
  `MODBUS_SERIAL_PORTS` 而某一端无法使用或探测帧没有到达时，串口测试组失败并注明原因；只有未设置该
  变量时才跳过。
- **重开串口。** 刚关闭的串口可能在几十毫秒内拒绝重新打开（CH340 驱动上见到过：`Access is denied`）。
  测试每次打开串口时，无论是作为原始流、通过 `Modbus_Server.start()` 还是通过串口 `Modbus_Client`，
  失败都每 20 ms 重试一次，最多 500 ms；超过时限仍失败才报错，所以真正被占用的串口仍会失败。重启测试
  在 `stop()` 与 `start()` 之间停顿 100 ms，因为它检查的是这两个调用，而不是驱动。库本身不重试：打开
  失败交给调用者处理。

### 串口测试启动脚本

`pnpm test:serial`（`test/run-serial.js`）用一条命令在串口的各个方向上运行串口测试。它只负责串口测试，
其余测试用 `pnpm test` 运行。参数有两种形式，第一个参数总是串口：

| 形式                                                          | 运行（按顺序）                               |
| ------------------------------------------------------------- | -------------------------------------------- |
| `pnpm test:serial COMn COMm`                                  | `COMn,COMm`，然后交换方向 `COMm,COMn`        |
| `pnpm test:serial COMn <local-udp-port> [<address>:<port>]`   | `COMn,<local-udp-port>[,<address>:<port>]`   |

- 各参数就是 `MODBUS_SERIAL_PORTS` 的各端，一个参数一端：`<local-udp-port>` 是透传设备发往的 UDP
  端口，例如 `pnpm test:serial COM4 502`；可选的第三个参数指明透传设备（见上文“给定的远端”），例如
  `pnpm test:serial COM4 502 192.168.89.2:4001`。
- UDP 端只运行一次：没有方向可以交换，串口的两种角色都在这一次运行中覆盖。
- 参数不符合任何一种形式，或会被 `MODBUS_SERIAL_PORTS` 拒绝（远端不是带端口的 IPv4 地址）时，打印原因和用法并以退出码 2 结束，不运行任何测试。启动脚本没有选项。
- 每次运行是一个 `node --test test/serial.test.js` 子进程，只为它设置 `MODBUS_SERIAL_PORTS`；它退出后
  才开始下一次运行，所以它占用的端口都已释放。两次运行之间不等待：重开串口由上面的打开重试兜底。
  两个串口时，每个方向都运行波特率扫描。
- 某次运行失败不影响其余运行。全部结束后，脚本把每次运行列为 `pass` 或 `FAIL`，任何一次失败则以退出码
  1 结束。
