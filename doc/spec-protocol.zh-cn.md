# 协议：帧格式、区间、功能码

> 本文是 [spec-protocol.md](spec-protocol.md) 的中文译本。

涵盖客户端与服务端共用的线路级规则。

## 传输方式与帧格式

| 传输方式       | 选用条件                                   | 帧格式                                             |
| -------------- | ------------------------------------------ | -------------------------------------------------- |
| TCP            | 客户端地址为字符串，`rtu: false`           | MBAP 头（7 字节）+ PDU。                            |
| RTU-over-TCP   | 客户端地址为字符串，`rtu: true`            | RTU 帧格式（单元 ID + PDU + CRC16），承载于 TCP 套接字。 |
| RTU            | 客户端地址不是字符串                       | 串口上的 RTU 帧格式。                               |

服务端的传输方式由 `options.port` 和 `options.rtu` 选择（见 `spec-server.zh-cn.md`）。

### MBAP 头（TCP）

| 偏移   | 字段               | 说明                                         |
| ------ | ------------------ | -------------------------------------------- |
| 0–1    | 事务 ID            | 由响应方原样返回；用于匹配。                 |
| 2–3    | 协议 ID            | 恒为 `0`；非零值无效。                       |
| 4–5    | 长度               | 此字段之后所有内容的字节数（单元 ID + PDU）。必须为 3–253。 |
| 6      | 单元 ID            | 单元地址（见“单元 ID”）。                    |
| 7…     | PDU                | 功能码 + 功能数据。                          |

### RTU 帧

`[unit_id: 1][function_code: 1][function data: n][crc16: 2 LE]`。PDU 长度（除末尾 2 个 CRC
字节之外的全部内容）必须为 3–253。RTU 没有事务字段。

### 单元 ID

单元 ID 的含义取决于传输方式，遵循 Modbus 的通行做法：

- **串行总线**（RTU，以及承载串行线路的 RTU-over-TCP）。`0` 是广播地址：广播写由每个从站执行，
  且没有任何从站应答。`1..247` 是各个从站的地址。`248..255` 由 Modbus 串行链路规范保留，不应分配
  给从站。从站只应答发给自己的请求。
- **TCP。** 没有广播；`0` 是普通的单元 ID。单元 ID 用于选择服务端后面的单元，如同经过网关。按惯例
  （Modbus TCP 实现指南），不需要单元路由时用 `0xFF`（255）寻址服务端本身；本库把它当作普通的
  单元 ID。

### 帧的界定

- **TCP。** 一次读取可能包含多个被合并的帧。接收方必须依据 MBAP 长度字段把这样的一次读取拆分成
  单独的帧，并分别处理；遇到格式错误的头则终止提取。
- **RTU（串口）。** 帧之间以至少 3.5 个字符时间的静默间隔分隔。接收方必须收集收到的字节，直到
  该静默间隔结束，并把收集到的字节当作一个帧。一次读取可能只携带帧的一部分。
- **RTU-over-TCP。** 流上没有帧间静默；帧的边界由功能码以及（若有）字节数所隐含的长度决定。

## 区间表示法

`read` 和 `write` 接受一个**区间**（range）：一个起始地址加一个长度，以及它所作用的表（或功能码）。
交给客户端的区间有两种形式，**严格由 JavaScript 类型决定**，绝不根据值去猜：

- **Modicon 字符串**，例如 `"40001,73"`：一个 Modicon 地址，带可选的长度；
- **结构化 PDU 区间**，即携带功能码、PDU 地址和长度的数组或对象。

数字字符串是 Modicon 字符串，必须匹配下面的表示法；`number` 绝不会被当作 Modicon 解读。例如
`"40001"` 是 Modicon，而 `pdu_addr` 为 `40001` 则是 PDU 地址 40001。

### Modicon 字符串

字符串匹配 `^(\d{5,6})(,(\d{1,4}))?$`：

- **5 位形式。** 首位是表选择符；其余 4 位是点号。
- **6 位形式。** 首位是表选择符；其余 5 位是点号。
- 两种形式选择下表中的同一组表，以位数区分，因此 `"40001"` 与 `"400001"` 指同一个寄存器。
- 可选的 `,N` 后缀 — 长度（寄存器/线圈个数），1–4 位数字。

| 首位数字 | 表                 | 读功能码 | 单写功能码 | 多写功能码 |
| -------- | ------------------ | -------- | ---------- | ---------- |
| `0`      | 线圈               | 1        | 5          | 15         |
| `1`      | 离散输入           | 2        | —          | —          |
| `3`      | 输入寄存器         | 4        | —          | —          |
| `4`      | 保持寄存器         | 3        | 6          | 16         |

示例：`"40001"` → 40001 处的 1 个保持寄存器；`"40001,73"` → 从 40001 开始的 73 个保持寄存器；
`"400001,73"` → 同一范围的 6 位写法；`"00001,16"` → 16 个线圈。

不匹配该表示法的字符串，或首位数字不是 `0, 1, 3, 4` 之一的字符串，都不是有效区间。

**编号起点。** Modicon 点号**默认从 1 开始**。客户端在构造时选择起点（默认 1 起始，也可按需选择
0 起始），并在客户端的整个生命周期内保持不变。该起点只作用于 Modicon 字符串，绝不作用于结构化的
PDU 区间。

| 起点            | 5 位点号      | 6 位点号      | PDU 地址        |
| --------------- | ------------- | ------------- | --------------- |
| 1 起始（默认）  | `1..9999`     | `1..65536`    | `point - 1`     |
| 0 起始          | `0..9999`     | `0..65535`    | `point`         |

### 结构化 PDU 区间

数组 `[func_code, pdu_addr, length]` 或对象 `{ func_code, pdu_addr, length }`：

- `func_code` — `number`，十进制功能码，取值为 `1, 2, 3, 4, 5, 6, 15, 16` 之一。
- `pdu_addr` — `number`，`0..65535` 范围内的整数。PDU 地址**永远是 0 起始**：它就是线路上携带的
  地址，原样发送。上面的编号起点不作用于它。
- `length` — `number`，`>= 1` 的整数。

每个字段都必须是 `number`；任何其他类型（数字字符串、`boolean`、`bigint` 等）或越界的值都使该
区间无效。

长度还受下文数量上限的约束（FC 5 和 6 时恰为 `1`），且区间必须在 PDU 地址空间内结束：
`pdu_addr + length - 1 <= 65535`。Modicon 字符串转换为 PDU 地址后也遵守这两条规则。客户端用各自的
错误信息报告违反情况，而不是当作无效区间（见 `spec-client.zh-cn.md`）。

示例：`[3, 256, 2]` 和 `{ func_code: 3, pdu_addr: 256, length: 2 }` 都表示从 PDU 地址 256 开始的
2 个保持寄存器，用 1 起始的 Modicon 表示法写作 `"40257,2"`。

### 线路上的地址转换

- **客户端。** Modicon 字符串被转换为 PDU 地址：1 起始编号（默认）时为 `point - 1`，0 起始编号
  时为 `point`；结构化 PDU 区间中的 PDU 地址原样发送。
- **服务端。** 服务端只使用 PDU 地址。它不做任何转换，Modicon 表示法也绝不出现在服务端：
  `vector` 收到的是线路上的原始（0 起始）PDU 地址，类型为 `number`。

## 功能码与 PDU 结构

支持：`1, 2, 3, 4, 5, 6, 15, 16`。其他任何功能码（出现在请求中，或非异常响应中）都会被拒绝。

| FC | 操作                     | 请求数据                              | 响应数据                              |
| -- | ------------------------ | ------------------------------------- | ------------------------------------- |
| 1  | 读线圈                   | 起始地址、数量                        | 字节数 + 打包的位                     |
| 2  | 读离散输入               | 起始地址、数量                        | 字节数 + 打包的位                     |
| 3  | 读保持寄存器             | 起始地址、数量                        | 字节数 + 寄存器字                     |
| 4  | 读输入寄存器             | 起始地址、数量                        | 字节数 + 寄存器字                     |
| 5  | 写单个线圈               | 地址、`0xFF00` / `0x0000`             | 回显地址 + 值                         |
| 6  | 写单个寄存器             | 地址、16 位值                         | 回显地址 + 值                         |
| 15 | 写多个线圈               | 起始地址、数量、字节数、打包的位      | 起始地址 + 数量                       |
| 16 | 写多个寄存器             | 起始地址、数量、字节数、寄存器字      | 起始地址 + 数量                       |

PDU 长度与功能码不匹配的帧会被拒绝（定长功能要求长度精确相等；多写请求要求 `7 + byte_count`）。

### 数量上限

Modbus 协议限制一个请求可以携带的点数：

| FC | 最大数量 |
| -- | -------- |
| 1、2 | 2000 个线圈 / 离散输入 |
| 3、4 | 125 个寄存器 |
| 15   | 1968 个线圈 |
| 16   | 123 个寄存器 |

客户端会拒绝超过其上限的请求（见 `spec-client.zh-cn.md`）；服务端以异常 `0x03` 应答这样的请求
（见“异常响应”）。

### 位打包

线圈值按 LSB 优先打包：请求中的第 *i* 个线圈占据第 `i >> 3` 字节的第 `i & 7` 位。读响应
报告 `ceil(quantity / 8)` 个数据字节。

## CRC-16（Modbus）

多项式 `0xA001`，初始值 `0xFFFF`，无最终异或。16 位结果以**小端**写入 RTU 帧的最后两个字节。
收到的 RTU 帧若 CRC 不匹配，则被拒绝。

## 异常响应

异常响应为 `[unit_id][function_code | 0x80][exception_code]`（RTU 追加 CRC，TCP 追加
MBAP）。客户端通过以 `` `response error: ${exception_code}` `` 拒绝待决事务来呈现该异常。
服务端会发出的异常码：

| 代码   | 含义                                      | 服务端何时发送                              |
| ------ | ----------------------------------------- | ------------------------------------------ |
| `0x01` | 非法功能                                  | 功能码不在所支持的集合内。                  |
| `0x02` | 非法数据地址                              | 所请求的区间结束于地址 65535 之后。         |
| `0x03` | 非法数据值                                | 数量超出上文的限制（`>= 1` 且不超过最大值）、字节数与数量不符（FC 15/16），或 FC 5 的值不是 `0xFF00` / `0x0000`。 |
| `0x04` | 服务器设备故障                            | 处理请求时某个 `vector` 函数抛出了异常。    |
| `0x0B` | 网关目标设备无响应                        | 仅限 TCP：请求寻址的单元 ID 不在服务端配置的接受范围内。在串行总线上，这样的请求不被应答。 |

对受支持的功能码，服务端按 Modbus 应用协议的顺序检查请求：先检查数据值（`0x03`），再检查地址
区间（`0x02`），之后才调用 `vector`（若抛出异常则为 `0x04`）。未通过检查的请求不会被执行。
